# ОСВЕД

Персональный Telegram-бот для новостей и осведомлённости: свои Telegram-каналы,
YouTube-каналы, публичные авторы X/Twitter, RSS и GitHub. Один экземпляр — один
владелец со своей базой, источниками и API-ключами.

## Что умеет

- Находить события, объединять дубли, исследовать источники и готовить новости.
- Принимать публичные Telegram-каналы по ссылке или пересланному посту, с подтверждением.
- Отслеживать YouTube-выпуски, отсеивать Shorts и учитывать полезность результатов.
- Открывать содержательную сводку видео в исходной карточке; выдавать PDF отдельным файлом.
- Читать публичные посты выбранных X/Twitter-авторов и выполнять тематический X-поиск через Monid.
- Добавлять X-профили в радар по ссылке `x.com/name`, `twitter.com/name` или `/x @name`.
- Расширять новость через «Подробнее» и «Статья» в той же карточке, с новыми источниками.
- Объяснять понятия из X/Twitter отдельными карточками: до двух в день по интересам.
- Сохранять реакции, комментарии, очереди, кеш и учёт расходов в SQLite.
- Показывать недельную карту и людей по уже сохранённым проверенным событиям.

Подписки при первом запуске пустые. Интересы и поиск настраиваются в `config/`.
Примеры для RSS/GitHub и X лежат в `examples/`; они подключаются только после копирования.

## Быстрый старт

Подготовь Docker с Compose, новый Telegram-бот от [BotFather](https://t.me/BotFather),
свой Telegram user ID, ключ [OpenRouter](https://openrouter.ai/settings/keys) и ключ
[Monid](https://app.monid.ai/access/api-keys). У обоих API нужен доступный баланс.

```sh
git clone https://github.com/SlavaXAi/osved.git
cd osved
cp .env.example .env
```

В `.env` заполни `TELEGRAM_BOT_TOKEN`, `ALLOWED_USER_ID`, `OPENROUTER_API_KEY`
и `MONID_API_KEY`. В `config/interests.yaml` укажи свои темы и цели.

```sh
docker compose build
docker compose run --rm newsfeed osved doctor
docker compose up -d
```

Напиши своему боту `/start`, добавь Telegram- и YouTube-каналы. Для X укажи своих
авторов в `config/x-authors.yaml` и/или запросы в `config/sensory-sources.yaml`.
Затем включи расписание:

```sh
docker compose exec newsfeed osved schedule-enable --live
```

Эта последняя команда разрешает фоновый сбор, поиск и LLM-запросы. До неё расписание
выключено; явные запросы YouTube-сводки и подробного разбора могут быть платными.
Изменения `.env` применяются через `docker compose up -d --force-recreate`.
Изменения YAML читаются из подключённого каталога `config/`.

**[Полный короткий гид: Telegram, YouTube, X и диагностика](docs/QUICKSTART.md).**

## Основные команды бота

| Команда | Назначение |
|---|---|
| `/start` | Начать работу |
| `/tgchannels` | Telegram-каналы: список, пауза, удаление |
| `/tg ссылка` | Добавить Telegram-канал через подтверждение |
| `/channels` | YouTube-каналы |
| `/channel ссылка` | Добавить YouTube-канал |
| `/x ссылка`, `/x @имя` | Добавить аккаунт X; ссылка на профиль работает и без команды |
| `/youtube`, `/videos` | Выпуск подходящих YouTube-видео |
| `/download ссылка` | Скачать YouTube/X как видео или MP3 в Telegram |
| `/circle` | Превратить присланное видео в видеокружок |
| `/report ссылка` | Полный PDF по YouTube-видео |
| `/sources`, `/radar` | Источники и состояние сбора |
| `/menu`, `/settings` | Семь выпусков и отдельное управление |
| `/news` | Новости сайтов и блогов |
| `/telegram`, `/twitter` | Выпуски Telegram-радара и X/Twitter |
| `/people`, `/institutions` | Действия людей и события организаций |
| `/bio` | Новая готовая биография; `status`, `pause`, `resume` — управление |
| `/status`, `/week`, `/people week` | Состояние ленты и недельные обзоры |
| `/preferences` | Предложения по реакциям без скрытого изменения интересов |

Выпуски включаются через `MENU_BATCHES_ENABLED=true`. Каждый материал приходит
отдельным сообщением. Команды используют готовый запас без платных вызовов;
«Подготовить новые» сначала показывает бюджет и требует подтверждения.
[Подробности выпусков и защиты от дублей](docs/menu-batches.md).

Обычная ссылка на YouTube-видео запускает короткую сводку. Полный PDF запрашивается
отдельной кнопкой или `/report`. Исходный транскрипт и результаты кешируются.

Скачивание медиа запускается отдельно: `/download ссылка` или кнопкой под вручную
присланным YouTube-роликом. Автоматическая лента не скачивается. Готовый файл можно
переслать в свой канал. [Форматы, ограничения и настройка больших файлов](docs/media-downloads.md).

Если YouTube RSS возвращает ошибку с хоста, можно включить резерв через Monid:
`YOUTUBE_RSS_FALLBACK_ENABLED=true`. Проверка канала стоит $0.0015; точные метаданные
каждого нового видео — ещё $0.0015 и кешируются. В одном цикле запрашиваются детали
не более пяти новых видео. Резерв соблюдает общие, суточные и месячные лимиты
сенсоров; бесплатный RSS проверяется первым. Незавершённые платные запросы
автоматически не повторяются. По умолчанию этот резерв выключен.

## Чтение и персонализация

Ежедневный отбор может учитывать оценки и историю успешного чтения через
`DAILY_PERSONALIZATION_ENABLED=true`. Личные веса настраиваются отдельно в
`config/daily-selection.yaml`; публичный пример нейтрален и выключен.
Критика подачи отделяется от интереса к теме, а открытие не считается лайком.
[Правила, журнал решений и проверка](docs/daily-personalization.md).

«Подробнее» заново пишет новость с целью прочитать три дополнительных источника
и примерно удвоить исходный текст. «Статья» целится в шесть дополнительных
источников всего и примерно вдвое больший текст, чем готовое «Подробнее».
Если сразу открыть статью, ориентир — четыре объёма исходной новости.
Это цели при наличии содержательных источников: неподтверждённые факты и
пустые абзацы ради объёма не добавляются.

Подготовка, результат и ошибка показываются в исходной карточке. Можно вернуться
к новости или «Подробнее»; длинный текст листается кнопками «← / →» в той же
карточке. Готовые результаты кешируются: переходы между ними не запускают
новое исследование. Неопределённый результат платного запроса блокирует
автоматический повтор.

YouTube-сводка состоит из связных абзацев с ориентиром 2000–2400 символов,
если в видео достаточно содержания. Ссылка на ролик находится внизу текста,
поэтому обычная пересылка Telegram сохраняет переход к видео. PDF приходит
отдельным файлом. Под результатами есть 👍/👎: это оценка общей полезности
для читателя. Открытие карточки само по себе не считается лайком.

Интересы задаются в `config/interests.yaml`; сохранённые оценки YouTube-результатов
учитываются при отборе. Понятийные карточки опираются на реально собранные
X-посты, профиль интересов и уже показанные понятия. Две карточки в день — верхняя
граница, без обязательного заполнения при отсутствии новых полезных понятий.
Для фокуса на AI coding, агентах, harness и domain-native продуктах можно добавить
эти темы в свой профиль и настроить тематические запросы из `examples/`.
Стартовая конфигурация не копирует профиль первоначального владельца.

Пределы дополнительных исследований задаются через
`NEWS_READER_EXPANDED_MAX_COST_USD` (по умолчанию 0.05) и
`NEWS_READER_ARTICLE_MAX_COST_USD` (0.08), вместе с общим бюджетом.
Понятийные карточки можно выключить через `CONCEPT_BRIEFS_ENABLED=false`.

## Границы текущей версии

Telegram-радар даёт события для исследования, а не копию всех постов каждого канала.
Новость требует прочитанного первоисточника; мнения и аналитика без него могут
остаться без карточки. Сбор выполняется по настроенному расписанию и получает
ограниченное окно последних постов; полнота архива и отсутствие пропусков не гарантируются.
Стартовый `RADAR_COLLECT_LIMIT=100` расширяет окно по сравнению с коротким образцом.

X/Twitter читает публичных авторов и поисковые результаты. Личная лента «Для вас»,
закрытые аккаунты и история просмотра не входят в обычное подключение. Для этого
режима не нужен Twitter API token, пароль или cookies; нужен Monid.

В `.env.example` включены учётные лимиты, в том числе для видео. Они не заменяют
лимиты на стороне провайдера и не являются банковской выпиской. VPS оплачивается отдельно.
Тексты источников, профиль интересов и ограниченные примеры реакций могут передаваться
используемым API. Круглосуточная работа требует постоянно включённого хоста.

## Разработка

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/). Для локальных запросов источников
также нужен Node 20+ и `npm install -g @monid-ai/cli@0.1.7`;
`monid keys add --key ... --label local` выполняется у себя, с собственным ключом.
Docker устанавливает Monid сам и использует `MONID_API_KEY` из окружения.

```sh
uv sync --frozen --extra dev
uv run osved --help
uv run ruff check app tests
uv run pytest
```

Тестовые профили в `tests/fixtures/config/` используются только в регрессионных тестах.
Биографическая рубрика с каталогом первоначального владельца и его серверные
скрипты в этот пакет не включены. Личные базы и настройки в репозитории отсутствуют.

Лицензия проекта — MIT. Сторонние ресурсы в `app/web/static/vendor/` сохраняют свои лицензии.
