# Один трек Яндекс Музыки в Telegram

Пришлите ссылку `https://music.yandex.ru/album/123/track/456` или
`https://music.yandex.com/track/456`. Также принимается `/download ссылка`.
Альбомы и плейлисты не скачиваются. Запрос доступен только владельцу в личном чате.

Бот присылает один MP3 через музыкальный плеер Telegram: отдельные поля названия и
исполнителя, встроенная ID3-обложка и миниатюра. Подпись, рекламные ссылки и кнопки
к самому аудио не добавляются. Временное сообщение прогресса удаляется после отправки.

Используется `yandex-music==3.2.2` и существующий FFmpeg. Получение и отправка не
вызывают LLM или Monid. Полный трек запрашивается через собственный доступ пользователя
к Яндекс Музыке. Короткий preview отклоняется по сравнению с длительностью из каталога.
Если сервис не отдаёт полный MP3 или обложку, файл не подменяется другой записью.

## Подключение

Один раз запустите на доверенном компьютере:

```sh
python -m app.media.yandex_music_auth --token-file /private/yandex-music-token.json
```

Подтвердите показанный код на официальной странице Яндекса. Команда не печатает
токен. Сохранённый файл имеет права `0600`; его нужно поместить в приватный
`DATA_DIR/yandex-music-token.json` бота, доступный пользователю процесса.
Альтернатива — секретная переменная `YANDEX_MUSIC_TOKEN`. Не добавляйте ключ в Git
и не отправляйте его сообщением Telegram. При истечении доступа подключитесь снова.

Скачивание использует существующую ограниченную очередь и временное хранилище.
Трек передаётся целым файлом в пределах текущего лимита Telegram (49 МБ для облачного
Bot API). После отправки сохраняется Telegram `file_id`, а временные файлы удаляются.
Повторная доставка того же входящего сообщения не создаёт второй MP3. Новая присланная
ссылка на тот же трек может вернуть сохранённый файл без повторного скачивания.
Состояние неопределённой отправки не повторяется автоматически.
